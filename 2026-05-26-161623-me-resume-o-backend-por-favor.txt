❯ oque seria esse tema builder?                                                 

● Padrão Builder — o que é

  É um padrão de criação de objetos do GoF (Gang of Four). A ideia central é
  separar a construção de um objeto complexo da sua representação final.

  O problema que ele resolve

  Imagina criar um Anuncio com 12 campos direto no construtor:

  // Telescoping constructor — difícil de ler, fácil de errar a ordem
  new Anuncio(conta, "Título", "Bovino", "Nelore", 10, 450.0, 24, MACHO, 3500.0,
   "Goiânia", "GO", "Descrição");

  Qual parâmetro é o quê? Se um campo é opcional, você passa null? E se tiver 20
   campos?

  A solução do Builder

  // Legível, seguro, campos opcionais ficam naturais
  new AnuncioConcretoBuilder()
      .conta(conta)
      .titulo("Nelore Premium")
      .especie("Bovino")
      .quantidade(10)
      .precoUnitario(3500.0)
      // .raca() → opcional, posso omitir
      .construir();

  Os 4 participantes (GoF)

  ┌─────────────────────┬────────────────────────┐
  │        Papel        │       No projeto       │
  ├─────────────────────┼────────────────────────┤
  │ Builder (interface) │ AnuncioBuilder         │
  ├─────────────────────┼────────────────────────┤
  │ ConcreteBuilder     │ AnuncioConcretoBuilder │
  ├─────────────────────┼────────────────────────┤
  │ Director            │ DiretorAnuncio         │
  ├─────────────────────┼────────────────────────┤
  │ Product             │ Anuncio                │
  └─────────────────────┴────────────────────────┘

  O Director conhece as "receitas" de montagem (ex: anúncio a partir de uma
  requisição HTTP). O ConcreteBuilder sabe como montar peça por peça. O cliente
  só fala com o Director.

  Quando usar

  - Objeto com muitos campos, especialmente opcionais
  - Quando a ordem de configuração importa
  - Quando você quer validar o objeto completo só no momento do construir()

  No seu caso o Anuncio é o exemplo perfeito: 12 campos, 4 opcionais, validação
  no construir().

  ---
  Opção 1 — Responsive (mais rápido)

  ---
  Opção 2 — Capacitor (recomendo)

  Envolve o React existente e gera um .apk (Android) e .ipa (iOS) real. É
  literalmente instalar um pacote e buildar.

  npm install @capacitor/core @capacitor/cli
  npx cap init
  npx cap add android
  npx cap build android

  Prós: app nativo real, acesso a recursos do dispositivo, mesmo código React
  Contras: precisa do Android Studio instalado para gerar o APK

  ---
  Recomendação

  Para trabalho acadêmico: Capacitor impressiona mais — você entrega um app
  instalável. Se o prazo for curto, começa pelo responsive que já resolve 80% e
  é mais rápido.

  Capacitor também precisa para ficar bonito no mobile).
