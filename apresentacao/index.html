Verificação da 3ª Forma Normal

1FN — Atomicidade ✓

Todos os atributos são atômicos. Endereço separado em município + estado. Sem grupos repetidos.

2FN — Dependência Total ✓

PKs são UUIDs simples. Dados de perfil separados em tabelas próprias (produtores, compradores, transportadoras).

3FN — Sem Dependência Transitiva ✓

Dados de rastreabilidade isolados na tabela rastreabilidade. Fotos isoladas em fotos_anuncio. Log em log_auditoria.

Atributos derivados → computed

preco_por_cabeca: GENERATED ALWAYS AS STORED
score_rastreabilidade: calculado via TRIGGER AFTER

Slide 6 · Derived Attributes

Atributos Derivados

Valores calculados automaticamente pelo SGBD — nunca inseridos manualmente.

GENERATED ALWAYS AS STORED

preco_por_cabeca

Coluna virtual persistida no disco. Calculada automaticamente toda vez que preco_total ou quantidade são alterados. Nunca pode ser inserida ou atualizada manualmente.

-- Definição na CREATE TABLE preco_por_cabeca NUMERIC(14,2) GENERATED ALWAYS AS (preco_total / quantidade) STORED, -- Exemplo com valores: -- preco_total: 190.000,00 -- quantidade: 50 -- preco_por_cabeca: 3.800,00 ←automático

PostgreSQL calcula e persiste a coluna automaticamente

AFTER TRIGGER

score_rastreabilidade

Score de 0–100% calculado pelo trigger trg_score_rastreabilidade a cada UPDATE na tabela rastreabilidade. Conta os booleanos verdadeiros e multiplica por 12,5.

-- 8 campos booleanos → score score := ( CASE WHEN NEW.gta THEN 1 ELSE 0 END + CASE WHEN NEW.brucela THEN 1 ELSE 0 END + CASE WHEN NEW.tuberculose THEN 1 ELSE 0 END + CASE WHEN NEW.aftosa THEN 1 ELSE 0 END + CASE WHEN NEW.raiva THEN 1 ELSE 0 END + CASE WHEN NEW.carbunculo THEN 1 ELSE 0 END + CASE WHEN NEW.dna THEN 1 ELSE 0 END + CASE WHEN NEW.organico THEN 1 ELSE 0 END ) * 12.5; -- 8 docs × 12.5 = 100%

Slide 7 · DDL

DDL — Data Definition Language

Criação das tabelas com todas as constraints exigidas.

Tabela principal: anuncios

CREATE TABLE anuncios ( id UUID PRIMARY KEY DEFAULT uuid_generate_v4(), produtor_id UUID NOT NULL REFERENCES usuarios(id), titulo VARCHAR(200) NOT NULL, especie VARCHAR(30) NOT NULL CHECK (especie IN ( 'bovinos','equinos', 'suinos','aves', 'ovinos','caprinos')), quantidade INTEGER NOT NULL CHECK (quantidade > 0), preco_total NUMERIC(14,2) NOT NULL CHECK (preco_total > 0), -- ATRIBUTO DERIVADO (computed) preco_por_cabeca NUMERIC(14,2) GENERATED ALWAYS AS (preco_total / quantidade) STORED, status VARCHAR(20) DEFAULT 'ativo' CHECK (status IN ( 'ativo','pausado', 'vendido','cancelado')) );

Constraints aplicadas

PRIMARY KEY

UUID gerado automaticamente em todas as 13 tabelas via uuid_generate_v4()

FOREIGN KEY

Referências com ON DELETE CASCADE onde aplicável (fotos, rastreabilidade, favoritos)

CHECK

Domínios controlados: especie, sexo, status, perfil, modalidade_frete, score BETWEEN 0 AND 100

UNIQUE

email, documento, cnpj, car — campos únicos em usuários e empresas. Chave composta em favoritos e cotacoes_frete.

NOT NULL

Atributos obrigatórios em todas as tabelas. Ex: nome, email, status, timestamps.

Slide 9 · Views

Views — Segurança e Relatório

View de Segurança vw_catalogo_publico

Expõe anúncios ativos sem revelar dados sensíveis do produtor (documento, telefone, endereço exato).

CREATE VIEW vw_catalogo_publico AS SELECT a.id, a.titulo, a.especie, a.raca, a.quantidade, a.sexo, a.peso_medio_kg, a.preco_total, a.preco_por_cabeca, -- derivado -- Faixa em vez do valor exato CASE WHEN a.preco_total < 50000 THEN 'Até R$ 50 mil' WHEN a.preco_total < 200000 THEN 'R$ 50–200 mil' ELSE 'Acima de R$ 200 mil' END AS faixa_preco, a.municipio, -- sem endereço exato a.estado, u.nome, -- sem CPF/CNPJ a.score_rastreabilidade, a.criado_em FROM anuncios a JOIN usuarios u ON u.id = a.produtor_id WHERE a.status = 'ativo';
View de Relatório vw_relatorio_negociacoes

Consolida propostas, contratos e usuários para relatório gerencial. Inclui variacao_preco calculada.

CREATE VIEW vw_relatorio_negociacoes AS SELECT p.id AS proposta_id, a.titulo AS anuncio, a.especie, a.quantidade, a.preco_total AS preco_anunciado, p.valor_proposto, -- Atributo derivado da VIEW ROUND( (p.valor_proposto - a.preco_total) / a.preco_total * 100, 2 ) AS variacao_preco, p.status AS status_proposta, uc.nome AS comprador, uv.nome AS vendedor, c.status AS status_contrato, p.criado_em FROM propostas p JOIN anuncios a ON a.id = p.anuncio_id JOIN usuarios uc ON uc.id = p.comprador_id JOIN usuarios uv ON uv.id = p.vendedor_id LEFT JOIN contratos c ON c.proposta_id = p.id;

Slide 10 · Triggers

Triggers — BEFORE e AFTER

⚡ BEFORE INSERT trg_validar_proposta

Executa ANTES do INSERT em propostas. Aborta a operação se as regras de negócio forem violadas.

CREATE FUNCTION fn_validar_proposta() RETURNS TRIGGER AS $$ DECLARE v_status VARCHAR; v_dup INT; BEGIN -- Regra 1: anúncio deve estar ativo SELECT status INTO v_status FROM anuncios WHERE id = NEW.anuncio_id; IF v_status <> 'ativo' THEN RAISE EXCEPTION 'Anúncio indisponível: %', v_status; END IF; -- Regra 2: sem proposta duplicada SELECT COUNT(*) INTO v_dup FROM propostas WHERE anuncio_id = NEW.anuncio_id AND comprador_id = NEW.comprador_id AND status = 'aguardando'; IF v_dup > 0 THEN RAISE EXCEPTION 'Proposta duplicada pendente'; END IF; -- Regra 3: sem autoproposta IF NEW.comprador_id = NEW.vendedor_id THEN RAISE EXCEPTION 'Comprador = vendedor'; END IF; RETURN NEW; -- permite o INSERT END; $$ LANGUAGE plpgsql;
🔍 AFTER UPDATE trg_audit_proposta_status

Executa DEPOIS do UPDATE em propostas. Registra toda mudança de status na tabela de auditoria.

CREATE FUNCTION fn_audit_proposta() RETURNS TRIGGER AS $$ BEGIN IF OLD.status <> NEW.status THEN INSERT INTO log_auditoria (tabela, operacao, registro_id, status_anterior, status_novo, alterado_em) VALUES ( 'propostas', 'UPDATE', NEW.id::TEXT, OLD.status, NEW.status, NOW() ); END IF; RETURN NEW; END; $$ LANGUAGE plpgsql; CREATE TRIGGER trg_audit_proposta_status AFTER UPDATE ON propostas FOR EACH ROW EXECUTE FUNCTION fn_audit_proposta();

Tabela log_auditoria: bigserial PK · tabela · operacao · registro_id · status_anterior · status_novo · alterado_em

Slide 12 · DQL

Queries — JOINs e UNION

INNER JOIN — Propostas com detalhes

SELECT p.id, a.titulo, a.especie, uc.nome AS comprador, uv.nome AS vendedor, p.valor_proposto, p.status FROM propostas p INNER JOIN anuncios a ON a.id = p.anuncio_id INNER JOIN usuarios uc ON uc.id = p.comprador_id INNER JOIN usuarios uv ON uv.id = p.vendedor_id WHERE p.status = 'aceita' ORDER BY p.criado_em DESC;

LEFT JOIN — Anúncios com/sem proposta

SELECT a.titulo, a.especie, a.preco_total, COUNT(p.id) AS total_propostas, MAX(p.valor_proposto) AS melhor_oferta FROM anuncios a LEFT JOIN propostas p ON p.anuncio_id = a.id WHERE a.status = 'ativo' GROUP BY a.id, a.titulo, a.especie, a.preco_total ORDER BY total_propostas DESC;

RIGHT JOIN — Transportadoras e cotações

SELECT t.razao_social, t.estado, COUNT(c.id) AS total_cotacoes, AVG(c.valor) AS valor_medio, MIN(c.valor) AS menor_cotacao FROM cotacoes_frete c RIGHT JOIN transportadoras t ON t.id = c.transportadora_id GROUP BY t.id, t.razao_social, t.estado ORDER BY total_cotacoes DESC;

UNION — Participantes ativos da plataforma

SELECT u.nome, 'Produtor' AS papel, p.nome_fazenda AS empresa FROM usuarios u JOIN produtores p ON p.usuario_id = u.id WHERE u.ativo = TRUE UNION SELECT u.nome, 'Transportadora' AS papel, t.razao_social AS empresa FROM usuarios u JOIN transportadoras t ON t.usuario_id = u.id WHERE u.ativo = TRUE ORDER BY papel, nome;

Slide 13 · DQL Avançado

Queries — EXISTS, IN e Ranking

EXISTS — Produtores com propostas aceitas

SELECT u.nome, u.email, p.nome_fazenda, p.estado FROM usuarios u JOIN produtores p ON p.usuario_id = u.id WHERE EXISTS ( SELECT 1 FROM propostas pr JOIN anuncios a ON a.id = pr.anuncio_id WHERE a.produtor_id = u.id AND pr.status = 'aceita' ) ORDER BY u.nome;

IN — Anúncios favoritados por compradores VIP

SELECT a.titulo, a.especie, a.preco_total, a.score_rastreabilidade FROM anuncios a WHERE a.id IN ( SELECT f.anuncio_id FROM favoritos f JOIN usuarios u ON u.id = f.usuario_id WHERE u.verificado = TRUE AND u.perfil = 'comprador' ) ORDER BY a.score_rastreabilidade DESC;

WINDOW FUNCTION — Ranking por espécie

SELECT a.especie, a.titulo, a.preco_total, a.score_rastreabilidade, RANK() OVER ( PARTITION BY a.especie ORDER BY a.score_rastreabilidade DESC, a.criado_em ASC ) AS posicao_ranking FROM anuncios a WHERE a.status = 'ativo' ORDER BY a.especie, posicao_ranking;
