Padrao Builder

"Separando a construcao de um objeto complexo da sua representacao, de modo que o mesmo processo de construcao possa criar diferentes representacoes."

— Gang of Four, Design Patterns, 1994

Por que Builder para o AgroPlace?
Os dominios do sistema possuem objetos com 7 a 14 campos obrigatorios e opcionais. A entidade Anuncio exige 12 parametros — especie, raca, peso, idade, sexo, quantidade, preco, cidade, estado, descricao, conta e titulo. Um construtor convencional se tornaria imediatamente ilegivel e impossivel de validar com seguranca.

O Problema
O anti-padrao: telescoping constructor

Um construtor com 12 parametros na mesma ordem — sem nomes, sem validacao, sem legibilidade:

// ANTI-PADRAO — construtor telescopico
new Anuncio(
  conta,
  "Lote Nelore Macho",
  "BOVINO",
  "Nelore",
  50,
  new BigDecimal("420.00"),
  24,
  SexoAnimal.MACHO,
  new BigDecimal("3800.00"),
  "Sobral",
  "CE",
  "Animais vacinados, guia GTA inclusa"
);

Consequencias diretas desta abordagem:

Ilegibilidade
Impossivel saber qual argumento e qual campo sem IDE. Parametro 5 e quantidade ou peso?
Sem validacao
Nenhum ponto central para checar pre-condicoes antes de criar o objeto
Acoplamento
Toda chamada depende da ordem exata dos parametros — qualquer refatoracao quebra o codigo
Campos opcionais
Forcado a passar null para campos opcionais como raca e descricao
A Solucao
Padrao Builder — GoF
Os 4 participantes
Builder
Interface que declara os metodos de configuracao para cada parte do produto. No AgroPlace: AnuncioBuilder, ContaUsuarioBuilder
ConcreteBuilder
Implementa a interface Builder, acumula o estado e executa a validacao em construir(). Ex: AnuncioConcretoBuilder
Director
Orquestra a sequencia de chamadas ao Builder. Conhece o processo de montagem, nao o objeto resultante. Ex: DiretorAnuncio
Product
O objeto complexo sendo construido. Construtor package-private — so pode ser criado via Builder. Ex: Anuncio
Fluxo de criacao
Client → Director → Builder → Product 
// No ServicoAnuncioPadrao.java
DiretorAnuncio diretor =
  new DiretorAnuncio(
    new AnuncioConcretoBuilder()
  );

Anuncio anuncio =
  diretor.construirDaRequisicao(
    conta, req
  );

O servico de aplicacao nao conhece os campos do anuncio — apenas delega ao Diretor, que conhece o processo.

DiretorAnuncio.java
public class DiretorAnuncio {

  private final AnuncioBuilder builder;

  public DiretorAnuncio(AnuncioBuilder b) {
    this.builder = b;
  }

  public Anuncio construirDaRequisicao(
      ContaUsuario conta,
      RequisicaoAnuncio req) {
    return builder
      .conta(conta)
      .titulo(req.titulo())
      .especie(req.especie())
      .raca(req.raca())
      .quantidade(req.quantidade())
      .pesoMedioKg(req.pesoMedioKg())
      .sexo(req.sexo())
      .precoUnitario(req.precoUnitario())
      .cidade(req.cidade())
      .estado(req.estado())
      .descricao(req.descricao())
      .construir();
  }
}

PerfilCorporativaConcretoBuilder.java — validar()
private void validar() {
  if (conta == null)
    throw new IllegalStateException(
      "Conta e obrigatoria");
  if (razaoSocial == null
      || razaoSocial.isBlank())
    throw new IllegalStateException(
      "Razao social e obrigatoria");
  if (cnpj == null
      || cnpj.isBlank())
    throw new IllegalStateException(
      "CNPJ e obrigatorio");
  if (cidade == null
      || cidade.isBlank())
    throw new IllegalStateException(
      "Cidade e obrigatoria");
  if (estado == null
      || estado.length() != 2)
    throw new IllegalStateException(
      "Estado invalido");
}
Principios SOLID
Como o Builder aplica SOLID
PrincipioComo o Builder aplica
S — SRP O Builder cuida exclusivamente da montagem e validacao do objeto. O servico de aplicacao cuida da regra de negocio. Responsabilidades claramente separadas.
O — OCP Para adicionar um novo campo em Anuncio, basta acrescentar um metodo na interface AnuncioBuilder e implementar no AnuncioConcretoBuilder — sem alterar o Diretor ou o servico.
L — LSP AnuncioConcretoBuilder e qualquer outro ConcreteBuilder sao substituiveis entre si sem quebrar o comportamento do DiretorAnuncio — que depende apenas da interface.
I — ISP Cada interface de Builder declara apenas os metodos relevantes ao seu produto. ContaUsuarioBuilder nao tem metodos de AnuncioBuilder — interfaces enxutas e especificas.
D — DIP DiretorAnuncio depende da abstracao AnuncioBuilder (interface), nao da implementacao concreta. O ConcreteBuilder e injetado no construtor do Diretor.
Resultado
Antes e depois
Antes — Telescoping Constructor
// 12 argumentos posicionais
// Zero validacao de pre-condicoes
// Construtor publico — qualquer
// codigo pode criar Anuncio invalido

new Anuncio(
  conta, titulo, especie,
  raca, quantidade, peso,
  idade, sexo, preco,
  cidade, estado, descricao
);
Sem validacao de campos obrigatorios
Ordem dos parametros causa bugs silenciosos
Campos opcionais forcam null explicito
Teste unitario legivel apenas com IDE
Depois — Builder + Diretor
// Diretor encapsula o processo
// validar() em construir()
// Construtor de Anuncio e
// package-private

diretor.construirDaRequisicao(
  conta, req
);

// Internamente, fluent chain:
builder.conta(conta)
       .titulo(req.titulo())
       ...
       .construir();
Validacao centralizada em validar()
Campos nomeados — legibilidade total
Campos opcionais simplesmente omitidos
Objeto invalido nunca sai do Builder
Conclusao
O que o Builder resolve no AgroPlace
Telescoping constructor eliminado
Os 3 modulos (anuncio, autenticacao, perfil) criavam objetos com 7–14 parametros. Builder substitui por uma API fluente nomeada.
Validacao no momento da construcao
O metodo validar() do ConcreteBuilder garante que nenhum objeto invalido chega ao repositorio — fail-fast antes do save().
Extensivel sem modificacao
Novos campos podem ser adicionados implementando novos ConcreteBuilders sem alterar o Diretor ou o servico — Open/Closed Principle.

O padrao Builder e a escolha natural quando um objeto requer muitos parametros de inicializacao, quando alguns sao opcionais, e quando a validade do estado e uma pre-condicao critica antes da persistencia.
