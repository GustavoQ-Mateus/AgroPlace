LEFT JOIN
Todos os registros da esquerda, mesmo sem correspondência
-- Todos os usuários e quantas propostas fizeram -- (inclui quem nunca fez proposta → NULL) SELECT u.name, u.role, COUNT(p.id) AS total_propostas, COALESCE(SUM(p.price_offered), 0) AS valor_total FROM users u LEFT JOIN propostas p ON p.buyer_id = u.id GROUP BY u.id, u.name, u.role ORDER BY total_propostas DESC;

UNION
Combina resultados de múltiplas queries em um único conjunto
-- Todos participantes de transações (vendedores + compradores) SELECT u.name AS nome, u.email, 'Vendedor' AS papel FROM users u WHERE u.role = 'produtor' AND EXISTS ( SELECT 1 FROM anuncios WHERE seller_id = u.id ) UNION SELECT u.name AS nome, u.email, 'Comprador' AS papel FROM users u WHERE u.role = 'comprador' AND EXISTS ( SELECT 1 FROM propostas WHERE buyer_id = u.id ) ORDER BY papel, nome;

IN · Subquery
Filtra com base em um conjunto retornado por subquery
-- Compradores que tiveram ao menos uma proposta aceita SELECT name, email, phone FROM users WHERE role = 'comprador' AND id IN ( SELECT DISTINCT buyer_id FROM propostas WHERE status = 'aceita' ) ORDER BY name; -- Variante: anúncios com pelo menos uma foto SELECT title, price_total FROM anuncios WHERE id IN ( SELECT DISTINCT anuncio_id FROM fotos_anuncio );

IN é ideal para listas pequenas ou estáticas. Para subqueries grandes prefira EXISTS — evita carregar todo o conjunto em memória.

TRIGGER · BEFORE INSERT
Valida dados antes de uma operação ser confirmada
DELIMITER $$ -- Impede proposta em anúncio não-ativo CREATE TRIGGER tg_valida_proposta BEFORE INSERT ON propostas FOR EACH ROW BEGIN DECLARE v_status VARCHAR(20); SELECT status INTO v_status FROM anuncios WHERE id = NEW.anuncio_id; IF v_status != 'ativo' THEN SIGNAL SQLSTATE '45000' SET MESSAGE_TEXT = 'Anúncio não está ativo para propostas'; END IF; END$$ DELIMITER ;
Fluxo do Trigger

BEFORE INSERT — executa antes do INSERT. Se o SIGNAL for ativado, a linha NÃO é inserida e o erro retorna ao cliente.

Protege a integridade de negócio sem precisar de validação na aplicação.

TRIGGER · AFTER UPDATE
Propaga mudanças após uma operação confirmada
DELIMITER $$ -- Aceitar proposta → fecha anúncio + cancela demais CREATE TRIGGER tg_fecha_anuncio AFTER UPDATE ON propostas FOR EACH ROW BEGIN IF NEW.status = 'aceita' AND OLD.status != 'aceita' THEN -- 1. Marca anúncio como vendido UPDATE anuncios SET status = 'vendido' WHERE id = NEW.anuncio_id; -- 2. Cancela demais propostas do lote UPDATE propostas SET status = 'cancelada' WHERE anuncio_id = NEW.anuncio_id AND id != NEW.id; END IF; END$$ DELIMITER ;
Propagação automática

AFTER UPDATE — executa após o commit do UPDATE. Pode modificar outras tabelas sem risco de recursão.

Uma única linha de SQL aciona 3 efeitos em cascata: proposta aceita, anúncio vendido, demais canceladas.

Criar índice para filtro por rastreabilidade ALTER TABLE anuncios ADD INDEX idx_trace (traceability_score); -- 3. Adicionar rating às propostas ALTER TABLE propostas ADD COLUMN rating TINYINT DEFAULT NULL COMMENT 'Avaliação 1-5 do comprador'; -- 4. Mudar nome de coluna ALTER TABLE transportadoras RENAME COLUMN nota_media TO avaliacao_media; -- Verificar nova estrutura DESCRIBE anuncios;
Estrutura após ALTER

ALTER TABLE em MySQL com InnoDB é online para ADD COLUMN em muitas versões — sem lock total da tabela.

Sempre teste em staging: ADD COLUMN NULL é seguro; MODIFY COLUMN pode exigir reescrita completa da tabela.
